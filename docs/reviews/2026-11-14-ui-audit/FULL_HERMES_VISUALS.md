# Full Hermes visual proposals
Updated 2026-11-15. Proposed concepts only; no settings or schedules were changed.

- [Voice and Settings](assets/04-full-hermes-settings-v1.png): nine settings groups, explicit profile/gateway scope, common setup and searchable advanced access.
- [Automation initial pass](assets/05-full-hermes-automations-v1.png): reviewed and superseded by the next render.
- [Automation refined](assets/06-full-hermes-automations-v2.png): corrected paused next-run state, multiple delivery checkboxes, unsaved-draft wording and absent-history links.

The earlier coding-only renders are historical composition studies, not the full-feature scope. Both new screens use fictional content. “In Hermes” means preserving run/history access; actual delivery payloads follow the backend contract, not image radio/checkbox geometry.

Critique: the Settings image is a common setup view, not the whole form. Advanced disclosure must actually open all relevant options; the down-chevron illustration alone proves nothing. “Lower latency” beside Live is illustrative copy and must not promise measured latency. No microphone was tested for this render. The automation's abbreviated weekday previews need real backend-computed dated/timezone-aware values. Run statuses in all images need actual event/report evidence. Model/provider search and live child trees remain specified in the design, not proven by these images.

Built-in image generation was used, with the previous workspace/settings concept as a style reference. Final prompts retained below.
