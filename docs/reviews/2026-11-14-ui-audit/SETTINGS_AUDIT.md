## Scope, persistence and apply semantics

Every edit should show **Connection → Profile** or **This device** or **Account**, plus effective value, whether overridden/inherited/default/managed, and when it takes effect. Hide the profile picker for a true single-profile setup, while keeping target identity available in details. Changing a scope clears drafts/revealed credentials and rejects late results from the prior owner. An All profiles read filter must never become an ambiguous write target.

The original scope store already warns about active bot profiles, carries concrete request-profile keys and distinguishes `null` from `undefined`: [settings-scope.ts:5](/Users/aldrinjoseph/.hermes/hermes-agent/apps/desktop/src/store/settings-scope.ts:5), [line 33](/Users/aldrinjoseph/.hermes/hermes-agent/apps/desktop/src/store/settings-scope.ts:33). Keep those differences explicit. Local model runtimes, native shortcuts and machine permissions are device-scoped; credentials/config/plugins commonly belong to `(connection, profile)`; billing belongs to its signed-in account.

## Masked secrets and configuration updates

Use three distinct secret states: **configured and unchanged**, **replacement draft**, **explicitly removed**. A mask is display-only. Focusing a stored key starts an empty replacement draft; blank/cancel leaves the existing value intact; removal uses the appropriate delete operation. Original key UI already separates these states: [credential-key-ui.tsx:44](/Users/aldrinjoseph/.hermes/hermes-agent/apps/desktop/src/app/settings/credential-key-ui.tsx:44), [custom-endpoints-settings.tsx:70](/Users/aldrinjoseph/.hermes/hermes-agent/apps/desktop/src/app/settings/custom-endpoints-settings.tsx:70).

Never round-trip a preview as a real key, even after a credential was rotated elsewhere. The backend deliberately rejects current, stale and legacy `«redacted…»`/bare mask shapes: [_common.py:149](/Users/aldrinjoseph/.hermes/hermes-agent/hermes_cli/web_routers/_common.py:149). Fetch full secrets only after an explicit Reveal request, keep them ephemeral, and clear them on close/scope change; do not put keys, tokens, private tickets, vault data or headers in URLs, logs, diagnostics, search indexing, local draft persistence or default exports. Token-storage capability must be truthful; preserve the existing explicit plaintext opt-in when secure storage is unavailable ([gateway-settings.tsx:531](/Users/aldrinjoseph/.hermes/hermes-agent/apps/desktop/src/app/settings/gateway-settings.tsx:531)). Managed locks remain authoritative.

Keep config patch, map replacement and raw replacement separate. `PUT /api/config` deep-merges untouched branches under the backend mutation lock ([config_env.py:122](/Users/aldrinjoseph/.hermes/hermes-agent/hermes_cli/web_routers/config_env.py:122)); deletion cannot be expressed by simply omitting a key. MCP's dedicated replacement endpoint is designed to persist removals and re-enabling ([api/mcp.ts:36](/Users/aldrinjoseph/.hermes/hermes-agent/apps/desktop/src/api/mcp.ts:36)); delegation routing has a corresponding owner API. Raw YAML replacement must preview scope and additions/removals, validate syntax/types/managed restrictions, protect concurrent edits, and offer a recoverable backup appropriate to the backend. Preserve reference expressions such as `${ENV_KEY}` rather than expanding secrets into documents.

Current import/export/reset call sites use config records directly ([index.tsx:211](/Users/aldrinjoseph/.hermes/hermes-agent/apps/desktop/src/app/settings/index.tsx:211)); this audit does not establish their exports are fully sanitized. The proposal requires default sanitized export with secret references/state only, scope-labelled import preview, and scoped reset review showing affected settings. No live export/import/reset was attempted.
